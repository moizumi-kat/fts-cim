 1. 原因　数の「型」が、SQL Server と SQLite で違いました
----------------------------------------------------------------

   いただいたログ

       File "c:\FTSCIM\verify.py", line 130, in <module>
       File "c:\FTSCIM\cim\repo.py", line 81, in _rate
         return int(a * 1000.0 / b) / 10.0
       TypeError: unsupported operand type(s) for *:
                  'decimal.Decimal' and 'float'

   SQL Server は numeric の列を **Decimal（10進数）** で返します。
   こちらの手元で使っている SQLite は **float（2進の浮動小数）** で返します。

   Decimal と float は、Python では掛け算ができません。そのため
   SQL Server でだけ止まりました。手元は SQLite なので見えませんでした。

   同じ原因で、その手前の2行も食い違っていました。

       [算] 実行予算 6-11071 受注率   115.1   ← 現物は 115.1
       [算] 検討物件 5-21251 受注率    99.3   ← 現物は 99.3

   同じ 115.1 に見えて「違う」と出たのは、float の 115.1 が
   ぴったりの 115.1 ではない（115.0999999…）ためです。
   10進で持っている Decimal の 115.1 とは一致しません。


----------------------------------------------------------------
 2. 直しかた　型をそろえ、COBOL と同じ10進で計算します
----------------------------------------------------------------

 (a) 取り出した時点で Decimal にそろえる  （cim\db.py）

     SQL Server でも SQLite でも、数は必ず Decimal で返すようにしました。
     これで**どちらのデータベースでも同じように動きます**。

         SQL Server : Decimal   → そのまま
         SQLite     : float     → Decimal に直す

     **COBOL も10進で計算しますので、Decimal のほうが現行に近い**です。
     float では 115.1 をぴったり持てません。

 (b) 受注率の計算を Decimal に直した  （cim\repo.py の _rate）

     float の定数（1000.0・10.0）で割り算していたのをやめ、
     COBOL の詰めかた（小数第1位で切り捨て）に合わせました。
     cim\cobol\arith.py の trunc／div を使います。現行の
     COMPUTE／MOVE と同じ詰めかたです。

 (c) 突き合わせも10進で比べる  （verify.py）

     「計算した数字」と「現物の紙の数字」を比べるとき、
     文字にしてから10進に直して比べます。型の違いで
     「同じ数なのに違う」と出ることがなくなります。

 (d) 書き戻しも通るようにした  （cim\db.py）

     SQLite は Decimal をそのままでは書けません（SQL Server は書けます）。
     逆向きの同じ不具合が起きないよう、こちらも直しました。


----------------------------------------------------------------
 3. 同じ見落としが起きないようにしました
----------------------------------------------------------------

   今回いちばんの問題は、**手元（SQLite）と本番（SQL Server）で
   振る舞いが違ったため、手元の試験では見つけられなかった**ことです。

   (a) の直しで、**手元の SQLite も SQL Server と同じ型を返します**。
   これ以降、この種の食い違いは手元の試験で必ず出ます。

   こちらで実行し、すべて通ることを確認しました。

       run.py --seed      ／ verify.py      ／ batch.py pegnip01
       点検\chk_len.py    ／ 点検\chk_cp932.py ／ report.py
       点検\kenshu.py（実データ21本）→ 検収 合格（1項目も違いません）
       点検\rep_same.py  → レプリ対象 22表 一致22／違い0
       画面14本           → 異常なし
