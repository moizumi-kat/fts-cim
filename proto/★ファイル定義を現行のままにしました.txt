================================================================
 ★ ファイル定義を現行のままにしました（第3版）
                                      FTS-CIM  2026-10-16
================================================================

 村上様より、次のご指示をいただきました。

   ・CIM からデータベースサーバへ**レプリケーションしているファイル**は、
     CAD・営業支援システム・古川工業のソフトなど、多数の周辺ソフトが
     同じファイルを使っている。ファイル定義が変わると、
     レプリケーションの見直しと周辺ソフト全部の改修が必要になり、
     工数が膨大になる。
     → **ファイル定義はそのままにしてほしい。**
   ・レプリケーションしていないファイルのテーブル定義は、
     **「COBOLファイル定義からSQL Serverテーブル定義への
       フィールド名変換仕様書」にもとづいて作ってほしい。**

 そのとおりに作り直しました。


----------------------------------------------------------------
 1. レプリケーション対象 … 定義体を一字一句そのまま
----------------------------------------------------------------

   お送りいただいた定義体（.sql）81本のうち、画面が使う **19表** を
   そのまま使っています。こちらで名前・型・桁を考えたものはありません。

     ・列名        定義体のまま（英大文字）
     ・型と桁      定義体のまま（char / nchar / decimal / numeric）
     ・NOT NULL    定義体のまま
     ・既定値      定義体のまま（' ' や (0) など）
     ・主キー      定義体のまま
     ・列の並び    定義体のまま

   合っているかは、機械で突き合わせて確かめられます。

       python 点検\rep_same.py  <定義体の .sql が入ったフォルダ>
         → 「レプリケーション対象 19 表： 一致 19 ／ 違い 0」

   対象の19表：
     AEJGFP   AGEGFP   AGEKFP   AJKNMP   AJUGFP   AJUKFP   AKAKMP
     ANAMMP   ASIYMP   ASOSMP   ATORMP   AUNKMP   CJISFP   CSHKMP
     GAICHUSF HANKANMF HOZAIMSF JITUYSFP KRIRIKFP


----------------------------------------------------------------
 2. レプリケーション対象外 … 変換仕様書どおりに生成
----------------------------------------------------------------

   残りの **9表** は、いただいた変換仕様書のとおりに作りました。

     ・集団項目（PICなし）は列にしない。実データを持つ要素項目だけ。
     ・列名は COBOL 英名をそのまま英大文字で。
     ・繰返し（OCCURS）は別テーブルにせず、1行の中に水平展開する。
       英名を _ で6文字に詰め、その後ろに "_" ＋ 連番。

         JUZENR（6文字） →  JUZENR_1   JUZENR_10
         NTMG1 （5文字） →  NTMG1__1   NTMG1__10
         TEST  （4文字） →  TEST___1   TEST___10

   この規則が正しいことは、**お送りいただいた定義体81本で検算**しました。
   レコードリストから同じ規則で列名を作り、実物の定義体と比べたところ、
   **63表が完全一致**しました。残り18表の違いは規則の違いではなく、
   レコードリスト側の綴り違い（DBNGCD／DENGCD など）と、
   レコードリスト作成後にファイルが拡張された分です。
   ＝ 規則どおりに作れば現行と同じ列名になる、と確認できました。

   対象の9表：
     DKANRISF  JURITUFF  KENTOUSF  KETUTESF  MEINIPFP
     NIPSYOFP  NOKIB4SF  SYOGAIFP  URIZSYFP


----------------------------------------------------------------
 3. ★ 試作は「別のデータベース」でお願いします（重要）
----------------------------------------------------------------

   レプリケーション対象の表は、**本番の表と名前が同じ**です
   （AJUGFP・ASOSMP など）。試作を本番と同じデータベースに作ると、
   取り違いの事故が起きかねません。

   そこで、試作用に別のデータベースをご用意ください。

       CREATE DATABASE FTSCIM_PROTO;

   接続文字列の DATABASE= を FTSCIM_PROTO に変えていただくだけです。

   なお、プログラム側にも歯止めを入れてあります。

     ・dbcheck.py / cleanup_old.py は、つなぎ先に「この試作が作らない
       現行ファイル名の表」が見つかったら、**その場で中止**します。
     ・cleanup_old.py が消すのは「列名が日本語の表（前の版が作ったもの）」
       だけです。列名が英名の表には絶対に触れません。


----------------------------------------------------------------
 4. 変えていないところ
----------------------------------------------------------------

   変えたのは **データベース層だけ**です。

     cim\schema_gen.py  表の定義（定義体＋変換仕様書から自動生成）
     cim\db.py          接続と CREATE 文の組み立て
     cim\seed.py        現物サンプルの投入
     cim\repo.py        SQL（現行の英名がそのまま出てきます）

   画面（11本）と画面遷移は作り直していません。
   数字も現物の紙と全数字一致のままです（verify.py でご確認いただけます）。


----------------------------------------------------------------
 5. 現行に無い表について
----------------------------------------------------------------

   聞き取り記録など、この試作だけで使う表には **Z_** をつけて、
   現行の名前と混ざらないようにしてあります。

     Z_HEARING  現場での聞き取り記録
     Z_ASOF     日報の「現在時点」（試作で時点を固定するため）


----------------------------------------------------------------
 6. 村上様にご確認いただきたいこと（1件）
----------------------------------------------------------------

   AGEKFP（原価ファイル項目）の原価項目情報は4回くりかえします。
   **1～4 がそれぞれ何を指すか**が分かりません。

   GENKA4CP.COB に「限度額 格納」として (2) を使う箇所があることから、
   いまは (1)＝総原価、(2)＝実行予算 として画面に出しています。
   これで合っているか、ご確認いただけますでしょうか。

   ※ 次の3つは現行の COBOL で裏が取れましたので、確認は不要です。
      KRIRIKFP 受注金額   JUCYUK_1～4 の合計（JUKAN1CF.COB）
      KRIRIKFP 増減受注   ZJUCYU_1～4 の合計（JUKAN1CF.COB）
      AGEGFP   受注予定金額 JYOTEI_1～4 の合計（GENKA4CP.COB）
