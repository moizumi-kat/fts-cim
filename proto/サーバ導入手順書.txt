 0. このソフトについて
----------------------------------------------------------------

   古川電気工業株式会社の積算・生産管理システム「FTS-CIM」を、
   富士通ASP(V29)＋COBOL から Python＋SQL Server へ入れ替える
   プロジェクトの **試作（プロトタイプ）** です。

   いまの CIM の画面のうち、営業日報まわり11画面を実際に動く形に
   してあります。残りの工程は一覧として収録しており、現場での
   聞き取り調査にそのまま使います。

   本番導入ではなく、**現場に見せて仕様を固めるための試作**です。
   そのため作り込んでいない点があります（15 をご確認ください）。

   構成は次のとおりです。各パソコンへのインストールは不要です。

     [各自のPC] --- 社内LAN(HTTP) ---> [サーバ1台] ---> [SQL Server]
      ブラウザのみ                  Python + waitress      データ

 2. 用意するもの
----------------------------------------------------------------

   ・サーバ機  Windows Server または Windows 10/11 の常時起動PC
               （この試作の規模なら CPU 2コア・メモリ 4GB で十分です）
   ・SQL Server（Express でも動きます）
   ・Python 3.13（サーバ機に1つ）★バージョンにご注意ください
   ・Microsoft ODBC Driver 18 for SQL Server（サーバ機に1つ）

   ※ 各自のパソコンには何も入れません。ブラウザだけです。
   ※ 必要な Python 部品（Flask・waitress・pyodbc）は vendor フォルダに
      同梱しています。インターネットにつながらないサーバでも入ります。


----------------------------------------------------------------
 3. SQL Server 側の準備
----------------------------------------------------------------

   (1) データベースを1つ作る

         CREATE DATABASE FTSCIM_PROTO;

   (2) このアプリ専用のログインを作る（SQL Server 認証の場合）

         CREATE LOGIN ftscim_app WITH PASSWORD = '(決めたパスワード)';
         USE FTSCIM_PROTO;
         CREATE USER ftscim_app FOR LOGIN ftscim_app;
         ALTER ROLE db_owner ADD MEMBER ftscim_app;

       ※ 最初は表を作る必要があるため db_owner にしています。
          表ができたあとは db_datareader ＋ db_datawriter に
          落としていただいてかまいません。

   (3) SQL Server 構成マネージャーで
       ・SQL Server 認証（混合モード）を有効にする
       ・TCP/IP を有効にする（既定のポート 1433）
       ・SQL Server サービスを再起動する

   ※ Windows 認証でお使いの場合は、5 の接続文字列で
      UID/PWD の代わりに Trusted_Connection=yes を指定します。
      その場合、9 のサービス実行アカウントに権限が必要です。


----------------------------------------------------------------
 4. サーバ機の準備
----------------------------------------------------------------

   (1) Python 3.13 を入れる   ★バージョンにご注意ください

       python.org の「Windows installer (64-bit)」から 3.13 を選びます。
       インストーラで「Add python.exe to PATH」に必ずチェック。

       ■ なぜ 3.13 なのか

         SQL Server につなぐ部品 pyodbc が Windows用の出来合い部品
         （ホイール）を配っているのは **Python 3.9～3.14** です。
         3.15 以降だと pip がソースから組み立てようとして

             error: Microsoft Visual C++ 14.0 or greater is required

         で止まります（C++のビルド環境が必要になります）。
         3.13 は、こちらで動作を確認している版です。

       ■ すでに別のバージョンが入っている場合

         消さなくて構いません。py ランチャーで使い分けられます。

             py -3.13 -m pip install -r requirements.txt
             py -3.13 dbcheck.py
             py -3.13 serve.py

         この場合、10 のタスク登録でもプログラムに py を指定し、
         引数を「-3.13 serve.py」としてください。

   (2) Microsoft ODBC Driver 18 for SQL Server を入れる
       「msodbcsql18」で検索して Microsoft のページから取得します。
       これが無いと SQL Server につながりません。

   (3) 確認（コマンドプロンプト）

         python --version
         → Python 3.13.x のように表示される

 5. ファイルの配置
----------------------------------------------------------------

   zip を展開し、01_ソフト の中身をサーバ機の任意の場所へ置きます。

        例）C:\FTSCIM\

   そのフォルダで、必要な部品を入れます（コマンドプロンプト）。

        cd /d C:\FTSCIM
        python -m pip install --no-index --find-links vendor Flask waitress pyodbc

   インターネットにつながるサーバなら、次でもかまいません。

        python -m pip install -r requirements.txt


----------------------------------------------------------------
 6. 接続先の設定
----------------------------------------------------------------

   環境変数を2つ設定します。★パスワードはソースに書きません。

   システム環境変数として設定してください
   （9 でサービス化する場合は必須。ユーザー環境変数だと読めません）。

        setx /M FTSCIM_DRIVER mssql

        setx /M FTSCIM_DSN "DRIVER={ODBC Driver 18 for SQL Server};SERVER=<サーバ名>;DATABASE=FTSCIM_PROTO;UID=ftscim_app;PWD=<パスワード>;TrustServerCertificate=yes"

   ・SERVER は  サーバ名  または  サーバ名\SQLEXPRESS
   ・証明書をきちんと入れている場合は TrustServerCertificate=yes を外せます
   ・Windows 認証なら UID/PWD の代わりに  Trusted_Connection=yes

   ★ setx は「次に開くコマンドプロンプトから」効きます。
     設定したら、**いまの画面を閉じて、開き直してください。**
     開き直さずに実行すると、SQL Server のつもりでも SQLite のまま
     動いてしまいます（接続確認.bat が気づいて教えます）。

   ★ 例文の <サーバ名> <パスワード> は、**実際の値に置き換えて**ください。
     そのまま貼ると、そのまま保存されます。
     名前付きインスタンスの場合は  SERVER=SRV01\\SQLEXPRESS  のように
     円記号を2つ重ねずに1つで指定します（コマンドプロンプトでは1つ）。

   設定したあと、念のため新しい画面で確認できます。

        echo %FTSCIM_DRIVER%
        echo %FTSCIM_DSN%

   うまくいかない場合も、表示をそのままお送りいただければ確認します

 9. 起動して動作確認
----------------------------------------------------------------

        サーバとして起動.bat      （または python serve.py）

   本番用のWebサーバ（waitress）で立ち上がります。
   同じ社内LANのパソコンから、ブラウザで

        http://<サーバのIPアドレス>:5000

   を開きます。IPアドレスは黒い画面に表示されます。

   ※ run.py / 起動.bat は 1人で試す用の開発サーバです。
      何人もが使うサーバでは serve.py をお使いください。

 10. Windows サービスとして常時起動にする
----------------------------------------------------------------

   サーバ機の再起動後も自動で上がるようにします。
   いちばん簡単なのは「タスク スケジューラ」です。

     (1) タスク スケジューラ →「タスクの作成」
     (2) [全般]  ・名前：FTS-CIM
                 ・「ユーザーがログオンしているかどうかにかかわらず実行する」
                 ・「最上位の特権で実行する」にチェック
     (3) [トリガー] 新規 →「スタートアップ時」
     (4) [操作]   新規 → プログラム：python
                        引数：serve.py
                        開始（作業フォルダ）：C:\FTSCIM
     (5) [設定]   「タスクが失敗した場合の再起動の間隔」を 1分・3回に

   NSSM などのサービス化ツールをお使いでしたら、そちらでも結構です。
   いずれの場合も FTSCIM_DRIVER / FTSCIM_DSN は
   **システム環境変数**に設定してください。


----------------------------------------------------------------
 11. ファイアウォールと利用者への案内
----------------------------------------------------------------

   ・サーバ機の Windows ファイアウォールで、受信の TCP 5000番 を
     「プライベートネットワーク」に対して許可します。
   ・利用者には  http://<サーバのIPアドレス>:5000  を案内します。
     社内DNSに名前を付けられるなら  http://ftscim:5000  が親切です。
   ・80番で使いたい場合は、環境変数 PORT=80 で起動できます。

 14. うまくいかないときの切り分け
----------------------------------------------------------------

   接続確認.bat が [NG] になるとき、よくある原因です。

   (1)「python は認識されていません」
       → Python 未導入、または PATH 未設定（4-(1)）

   (2)「pyodbc が入っていません」
       → 5 の pip install を実行してください

   (3)「Data source name not found」「ドライバが見つかりません」
       → ODBC Driver 18 が未導入（4-(2)）。
         接続確認.bat が出すドライバ一覧に
         「ODBC Driver 18 for SQL Server」があるか確認

   (4)「Login failed for user」
       → ログイン名・パスワードの誤り、
         または SQL Server 認証（混合モード）が無効（3-(3)）

   (5)「Cannot open database "FTSCIM_PROTO"」
       → データベース未作成、またはユーザーに権限が無い（3-(1)(2)）

   (6)「サーバーへの接続を確立できませんでした」
       → SERVER 名の誤り／TCP/IP が無効／1433番がファイアウォールで
         閉じている／SQL Server Browser が停止（名前付きインスタンス時）

   (7)「SSL Provider … certificate chain」
       → 接続文字列に TrustServerCertificate=yes を付けてください

   (8)「CREATE TABLE permission denied」
       → ユーザーに db_owner（または CREATE TABLE 権限）が必要（3-(2)）

   (9)「Microsoft Visual C++ 14.0 or greater is required」
       （pip install pyodbc の途中で出る）
       → Python のバージョンが新しすぎます。pyodbc の出来合い部品は
         3.9～3.14 まで。**Python 3.13 を入れてください**（4-(1)）

   (10)「つなぎ先 : SQLite」と出る（SQL Server のつもりなのに）
       → setx の直後で、いまの画面に反映されていません。
         コマンドプロンプトを閉じて開き直してください（6）

   (11) 接続文字列に <サーバ名> が残っている
       → 手順書の例をそのまま貼っています。実際の値に置き換えて
         setx をやり直してください（6）

   (12) C:\FTSCIM に ftscim.db ができている
       → SQLite として動いたときに作られたファイルです。
         SQL Server に切り替えたあとは使いません。消してかまいません。

 15. いまの試作で割り切っていること
----------------------------------------------------------------

   試作として、次は作り込んでいません。本番化の際にご相談させてください。

   (1) 認証・権限
       ログインがありません。社内LANにつながっている方なら誰でも
       見られます。誰が記録したかは、入力していただいたお名前だけです。

   (2) 通信の暗号化
       HTTP（平文）です。社内LAN内での利用を前提にしています。
       HTTPS にする場合は、前段に IIS か nginx を置く形になります。

   (3) 更新の履歴
       目標メンテなどで、誰がいつ変えたかの記録を残していません。

   (4) 既存データの移行
       いまはサンプルだけです。ASP から SQL Server へ実データを移す
       段取り（どのファイルを、いつ、どう移すか）は別途詰める必要があります。

   (5) 同時更新のぶつかり
       同じデータを2人が同時に直したときの扱いを決めていません。

   (6) SQL Server 実機での動作確認
       表の定義とSQL文は、SQL Server（T-SQL）として解析できることを
       機械的に確かめてあります（点検フォルダ参照）。

         ・表の定義＋実行時のSQL 計249文 … すべて解析OK
         ・ソース中のSQL 32文（? のまま）  … すべて解析OK
         ・表名・列名と T-SQL 予約語の衝突 … なし

       ただしこれは「構文として通る」ことの確認であり、
       **実機のSQL Serverでの動作確認はこれからです。**
       7・8 の結果をお送りいただくことで完了します。

 付録B：bat ファイルが入っていない場合（コマンドでの実行）
----------------------------------------------------------------

   メール・チャット・クラウドの多くは、実行ファイル（.bat など）を
   含む圧縮ファイルを自動で止めます。そのため、送付の都合で
   bat ファイルと vendor フォルダを外した版をお渡しすることがあります。

   その場合も、コマンドプロンプトで同じことができます。

     スタート →「cmd」→ コマンドプロンプトを開き、

        cd /d C:\FTSCIM          ← ファイルを置いた場所

     を実行してから、下の表のコマンドを打ってください。

     bat ファイル            同じことをするコマンド
     --------------------    ------------------------------------
     はじめて実行.bat        python -m pip install -r requirements.txt
                             python run.py --seed
     接続確認.bat            python dbcheck.py
     確認.bat                python verify.py
     確認結果を保存.bat      python report.py
     サーバとして起動.bat    python serve.py
     起動.bat                python run.py
     社内LANに公開して起動   set FTSCIM_HOST=0.0.0.0
                             python run.py

   ■ vendor フォルダ（Python部品）が入っていない場合

     インターネットにつながるサーバなら、これだけです。

        python -m pip install -r requirements.txt

     つながらないサーバの場合は、つながる別のPCで

        python -m pip download -r requirements.txt -d vendor --platform win_amd64 --python-version 3.11 --only-binary=:all:

     として vendor フォルダを作り、サーバへコピーしてから

        python -m pip install --no-index --find-links vendor -r requirements.txt

     としてください。
     （Python のバージョンが 3.11 以外の場合は、その番号に変えてください）
