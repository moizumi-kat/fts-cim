 1. 20日締めの月度（TUKICHKP.COB の移植）
----------------------------------------------------------------

   「当社は20日締め。10月度は9月21日から10月20日まで」

   現行のソースにも、そのとおり書かれておりました。
   TUKICHKP.COB（PEGNIP01.CL の STEPC から呼ばれる月度チェック）

       IF    IN-DAY   >  20
         THEN  IF  IN-MONTH = 12  THEN  WK-MONTH = 1
                                  ELSE  WK-MONTH = IN-MONTH + 1
         ELSE  WK-MONTH = IN-MONTH
       IF    WK-MONTH  NOT = IN-GATUDO  → エラー

   そのまま移しました（cim\cobol\tukichkp.py）。

       20260920 → 9月度      20261020 → 10月度
       20260921 → 10月度     20261021 → 11月度
       20261221 → 1月度（12月は翌年1月へ）

       10月度の期間 ＝ 20260921 ～ 20261020
       1月度の期間  ＝ 前年20261221 ～ 20270120

 2. ジョブの流れも現行どおりに分けました
----------------------------------------------------------------

   受注率ファイルの作成は、現行では**2本のプログラム**です。
   1本にまとめていたのを、現行と同じ順序に分けました。

       PEGNIP01.CL
         STEPC   月度チェック              TUKICHKP.COB
         STEP38  当月受注率データのクリア  JUHEN2CD.COB  ← 全件 DELETE
         STEP39  当月受注率ファイル作成    JUHEN2CF.COB  ← READ→ADD→REWRITE
                                                           / INVALID→WRITE

   動かしかた

       py -3.13 batch.py pegnip01 20261020 10
           STEP C  月度チェック … 最終更新日 20261020／指定月度 10
             月度チェックＯＫ … 10月度＝20260921～20261020
           STEP38  当月受注率データのクリア … n 件を削除
           STEP39  当月受注率ファイル作成   … n 件を作成

       月度が合っていなければ、現行と同じくそこで止まります。

           py -3.13 batch.py pegnip01 20260921 9
             [中止] 月度が合っていません。20260921 は 10月度です（20日締め）。

   JUHEN2CF は、既にある行には**足しこみ**（READ→ADD→REWRITE）、
   無ければ新しく書く（INVALID→WRITE）という現行の動きにしました。
   作成日・作成時間・作成端末も現行どおり書き込みます。

 3. 全項目つき合わせの道具（点検\compare_db.py）
----------------------------------------------------------------

   「現行と同じ入力を入れ、処理後のデータベースの中身が
     全てのデータ項目で同じかどうかで確認したい」

   そのための道具を作りました。

       py -3.13 点検\compare_db.py  "(正解CSVの入ったフォルダ)"
       py -3.13 点検\compare_db.py  "(フォルダ)" JURITUFF      ← 表を指定
       py -3.13 点検\compare_db.py  "(フォルダ)" --with-time    ← 日時も比べる

   正解CSV＝現行システムで同じ入力を処理したあとのファイルの中身です。
   表名と同じ名前の .csv を置いてください。

   比べかた
     ・主キーでレコードを対応づけ、**列を1つずつ**比べます
     ・char／nchar は後ろの空白を無視します（現行は固定長）
     ・数値は値として比べます（0 と 0.0 と "0" は同じ）
     ・作成日・作成時間・更新日・更新時間・端末ＩＤは実行のたびに
       変わるので既定では比べません（--with-time で比べられます）
     ・ちがいが1件でもあれば終了コード 1 で終わります

   出かた（実際に動かした結果）

       ■ 現行システムの処理結果との突き合わせ（日時・端末ＩＤを除く全項目）
         AJUGFP     件数   1181 ／ 正解   1181   一致
         ANAMMP     件数    357 ／ 正解    357   一致
         ASOSMP     件数    545 ／ 正解    545   一致
       すべての項目が一致しました。

   わざと食い違わせると、ちゃんと見つけます。

         AJUGFP     件数   1180 ／ 正解   1181   ちがい 3 件
           SEIBAN=511003 こちらに無い
           SEIBAN=511001 JYOTEI  こちら 40001   正解 40000
           SEIBAN=511002 KENMEI  こちら わざと変えた件名  正解 三沢米軍（Ｋ－ＳＰＡＮ）

 4. この確認のしかたに必要なもの
----------------------------------------------------------------

   「同じ入力 → 同じ出力」を確かめるには、処理の**前**と**後**の
   両方のファイルが要ります。

     (a) 入力  処理前の現行ファイルの中身（CSV）
     (b) 正解  同じ処理を現行システムで動かしたあとの中身（CSV）

   受注率の確認であれば

     (a) KRIRIKFP 集約履歴ファイル ／ SYOGAIFP 受注率計算対象外ファイル
         （PEGNIP01.CL を動かす前のもの）
     (b) JURITUFF 当月受注率ファイル
         （PEGNIP01.CL を動かしたあとのもの）
     あわせて、その実行のときの 年度・月度・最終更新日

   これがあれば

       py -3.13 load_csv.py  "(a のフォルダ)"
       py -3.13 batch.py pegnip01 (最終更新日) (月度)
       py -3.13 点検\compare_db.py  "(b のフォルダ)" JURITUFF

   で、現行と同じ結果になるかを全項目で機械的に確かめられます。
