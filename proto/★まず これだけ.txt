 ★ 第3版でエラーが出た件は、原因が分かり直しました。

 この版でお願いしたいのは、次の4つだけです。


----------------------------------------------------------------
 【1】★試作用のデータベースを1つ作る（この版からのお願い）
----------------------------------------------------------------

   村上様のご指示で、レプリケーション対象のファイルは
   **定義体のままの名前**（AJUGFP・ASOSMP …）で表を作ります。
   これは**本番の表と同じ名前**です。
   取り違いの事故を防ぐため、試作は別のデータベースでお願いします。

       CREATE DATABASE FTSCIM_PROTO;
       GO
       USE FTSCIM_PROTO;
       GO
       CREATE USER ftscim_app FOR LOGIN ftscim_app;
       ALTER ROLE db_owner ADD MEMBER ftscim_app;
       GO

   そのうえで、接続文字列の DATABASE= を書き換えてください。

       setx /M FTSCIM_DSN "DRIVER={ODBC Driver 18 for SQL Server};SERVER=10.1.110.120;DATABASE=FTSCIM_PROTO;UID=ftscim_app;PWD=(パスワード);TrustServerCertificate=yes"

   ※ プログラム側にも歯止めを入れてあります。もし本番のデータベースに
      つながっていると、dbcheck.py / cleanup_old.py はその場で中止します。


----------------------------------------------------------------
 【2】このフォルダの中身を、新しいものに入れ替える
----------------------------------------------------------------

   新しい zip を展開し、01_ソフト の中身を C:\FTSCIM に上書きして
   ください。ftscim.db と 確認結果.txt は上書きされません。
   Python・ODBCドライバの入れ直しは不要です。

   ※ 10/14 の版からの変更点は
     「★ファイル定義を現行のままにしました.txt」をご覧ください。
      列名が日本語から**現行の COBOL 英名**に変わっています。


----------------------------------------------------------------
 【3】前の版が作ったテーブルを片付ける
----------------------------------------------------------------

      cd /d C:\FTSCIM
      py -3.13 cleanup_old.py            ← 何が消えるか表示（消しません）
      py -3.13 cleanup_old.py --yes      ← 実際に消す

   消すのは次の2つだけです。
     (1) 10/14 より前の版の表（busyo・nip_jisseki など20表）
     (2) 10/14 の版が作った、**列名が日本語**の表

   列名が英名の表には**絶対に触れません**（本番の表かもしれないため）。
   新しいデータベース FTSCIM_PROTO で始める場合は、
   「片付けは不要です」と出れば、それで結構です。


----------------------------------------------------------------
 【4】取り込みと確認
----------------------------------------------------------------

      cd /d C:\FTSCIM

      py -3.13 dbcheck.py          表と件数の確認
      py -3.13 run.py --seed       現物サンプルを入れる
      py -3.13 verify.py           現物の紙と数字が合うか照合
      py -3.13 report.py           結果を 確認結果.txt にまとめる

   dbcheck.py に、現行ファイル名のテーブルが28個ならび、
   最後に「[OK] どの表も、列が定義どおりでした。」と出れば成功です。

      AJUGFP     受注ファイル鑑          ← 定義体そのまま
      ASOSMP     組織マスタ              ← 定義体そのまま
      KRIRIKFP   集約履歴ファイル        ← 定義体そのまま
      NIPSYOFP   営業日報照会マスタ      ← 変換仕様書で生成
      JURITUFF   当月受注率ファイル      ← 変換仕様書で生成
      …

   定義体どおりになっているかは、機械でも突き合わせられます。

      py -3.13 点検\rep_same.py  <定義体の .sql が入ったフォルダ>
        → 「レプリケーション対象 19 表： 一致 19 ／ 違い 0」


----------------------------------------------------------------
 【参考】Python 3.13 について（対応済み）
----------------------------------------------------------------

   Python 3.15 では pyodbc が入りません（出来合いの部品が
   配られているのは 3.9～3.14 まで）。py -3.13 をお使いください。


----------------------------------------------------------------
 パスワードの件（お願い）
----------------------------------------------------------------

   前回チャットに平文で流れたパスワードは、変更をお願いします。

        ALTER LOGIN ftscim_app WITH PASSWORD = '(新しいパスワード)';

   変更後は FTSCIM_DSN の PWD= も合わせて書き換えてください。
