# FTS-CIM　Python版 試作（プロトタイプ）

古川電気工業株式会社／積算・生産管理システム（FTS-CIM）の、**実際に動く**Python版です。
富士通ASP V29 + COBOL85 + FACAM CL を、**Python + データベース**へ置き換えられることを
小さく・確実に確かめるために作りました。

---

## 動かし方

```
pip install -r requirements.txt     # Flask だけです
python3 run.py                      # http://127.0.0.1:5000 を開く
```

初回はデータベース（`ftscim.db`）が自動で作られ、現物サンプルが入ります。
入れ直したいときは `python3 run.py --seed`。

数字が現物の紙と合っているかは、いつでもこれで確かめられます。

```
python3 verify.py
```

## 確かめたこと（方針1-1：裏取り）

* **画面遷移**は、村上様提供の遷移図だけでなく、**実ソース**（NPJYU4CS／NPJYU5CS と
  JYUSYORI・SZUGAMEN・URIGAMEN・JHYSYORI・GENSYOR1・BUTSYOR1・SINSYORI・KETGAMEN）で
  選択肢を1つずつ確認しました。**Ｋが受注一覧に無い**のもソースで確認したとおりです。
* **Ｇの分岐**は、COBOLと同じく「物件検討ファイルにその製番のレコードがあるか」で
  実際にデータベースを引いて分けています（決め打ちではありません）。
* **数字**は `verify.py` で現物の紙と全数字が一致することを確認済みです。
  * 金額の「計」＝明細の単純合計
  * **達成率＝受注実績 ÷ 受目標 ×100 の小数第2位切り捨て**
    （19,725/36,000＝54.79…→**54.7**。四捨五入だと54.8になり現物と合わない。
     NPJYU5CS.COB が小数2桁で ROUNDED したあと1桁の画面項目へ MOVE＝切り捨て、と一致）
  * **受注率＝受注予定金額 ÷ 標準原価 ×100。**
    計は率を平均せず、**金額と原価をそれぞれ足し込んでから割る**
    （茂泉様 2026-10-13 のご説明。JUHEN2CF.COB「日次受注登録処理」の
     `COMPUTE WK-JYURITU = 率－受注予定金額 / 率－標準原価` で裏取り。
     新規のみ対象／受注率計算対象外ファイルの製番は除外）
  * **「当受注」＝当日受注**。NPJYU5CS.COB の
    `COMPUTE WK-TOJITU = 営業－受注実績額 － 営業－受注当日累計`（その日ぶん）
* **目標の登録単位**は、村上様2026-10-13のご回答どおり
  **年度額を12で割ったひと月分を年度初めに一度だけ**登録します。

### 受注率について

現物の紙には受注予定金額・標準原価がのっていないため、いまは当月受注率ファイル
（`nip_juritsu` 表＝本物の JURITUL1 と同じ構造。部所別・本部計・総合計がすべて入る）の
率をそのまま出しています。**履歴ファイルがつながれば、上の式でSQLが計算します**
（`repo.juritsu()` / `repo.nippou()` に実装済み）。

式の向きは、現物のうち受注金額と総原価が両方のっている唯一の例で検算しました。
検討物件 5-21251：**122,038 ÷ 122,860 ＝ 99.3** ＝ 現物の受注率 99.3。

## 現場での聞き取りに使う

画面を見せながら、その場で記録できます。

1. 左のメニューから工程を開く（動く画面はそのまま触ってもらえます）
2. 画面右下の **「この工程を聞き取り」** を押す
3. その工程の種別（帳票／照会／登録・更新／処理・運用）に合わせた設問が出るので、
   聞きながら入れていく。部署・お名前・日付は前回の値が残ります
4. 「この工程をどうするか」で **残す（そのまま）／残す（変える）／やめる／保留・要相談** を選ぶ
5. 「記録する」

* 記録した工程は、左メニューに緑の **聞** が付きます（どこまで進んだか一目で分かります）
* 右下の **「一覧」** で、工程ごとの進み具合と全記録を確認。大分類・判定・ことばで絞り込めます
* **「CSVで取り出す」** でExcelにそのまま取り込めます（BOM付きUTF-8）

設問は `cim/hearing.py` に書いてあります。現場で聞きにくい言い回しがあれば、
ここを直すだけで全工程に反映されます。

## データについて

入っているのは**村上様・茂泉様からいただいた現物の紙の値だけ**です。作った数字はありません。

* 営業日報（26年9月30日現在）……全8営業所
* 日報内訳の受注／出図／売上一覧、受注票、実行予算、工程進捗……**部所11 北日本支店・2026年10月度**
* 検討物件……製番 **5-21251**（「検討あり」の例としていただいたもの）

サンプルの無い拠点・製番を開くと、画面に「まだ投入していません」と出ます。
勝手に埋めない方が、どこまで裏が取れているかが分かるためです。

## 社内サーバ＋SQL Server で動かす

```
[各自のPC] --- 社内LAN(HTTP) ---> [サーバ] ---> [SQL Server]
 ブラウザのみ                  Python+waitress     データ
```

各パソコンへのインストールは不要です。通しの手順は **サーバ導入手順書.txt**。

```
set FTSCIM_DRIVER=mssql
set FTSCIM_DSN=DRIVER={ODBC Driver 18 for SQL Server};SERVER=…;DATABASE=FTSCIM;UID=…;PWD=…
python dbcheck.py      # つながるか確認（パスワードは伏せて表示）
python run.py --seed   # 表を作って現物サンプルを投入
python verify.py       # 現物の紙と数字が合うか照合
python serve.py        # 本番用サーバ(waitress)で起動
python report.py       # 上の確認結果を 確認結果.txt にまとめる
```

* `run.py` は Flask の開発サーバです。**何人も使うサーバでは `serve.py`**（waitress）を使います。
* 方言の違い（`IDENTITY` / `IF NOT EXISTS`）は `cim/db.py` の `ddl()` が吸収します。
  表の定義は1つだけ持ち、SQLite用とSQL Server用を書き分けていません。
* 置換パラメータは sqlite3 も pyodbc も `?` なので、`repo.py` / `hearing.py` の
  SQL文は共通のままです。SQLite専用の書き方（`INSERT OR REPLACE`・`executemany`）は外してあります。
* パスワードはソースに書かず、環境変数 `FTSCIM_DSN` から読みます。
  `dbcheck.py` の表示でも伏せ字にします。
* 聞き取りの「部署・お名前」は**ブラウザごと**（Cookie）に覚えます。
  共用サーバで、他の方が入れた値を引っぱらないためです。

**※ SQL Server 実機での動作確認はまだです。** 表の定義とSQL文は両対応に
してありますが、サーバをご用意いただいたうえで通しの確認をさせてください。

## 中身

```
run.py          起動
verify.py       現物の紙との照合
cim/config.py   接続先（ここだけ差し替えればSQL Serverへ）
cim/db.py       接続と表の定義（ASPのファイルと1対1）
cim/seed.py     現物サンプルの投入
cim/repo.py     業務の問合せ（SQLはここだけ。集計の規則もここ）
cim/web.py      画面と遷移（Flask）
cim/koutei.py   405工程のメニュー
cim/templates/  画面のひな形
data/           405工程の一覧
```

**画面にSQLを書かない／業務の判断は `repo.py` に集める**という作りにしてあります。
工程を足すときは、表を1つ足して `repo.py` に関数を1つ、画面を1枚、の繰り返しです。
